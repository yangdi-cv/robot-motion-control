步态执行与反馈时序增强报告

2026年11月12日｜机器人控制算法阶段进展

摘要

本轮延续上一阶段倒立摆与有限脚掌平衡实验，将后续问题分为反馈时序、步态可执行性和多关节动力学三个层次。反馈层增加独立的传感器时钟、抖动、丢帧、乱序和偏置漂移；规划层增加双支撑、连续摆脚和有限候选的步时调整；动力学层建立带浮动基座、髋膝踝和真实脚掌接触的平面双足，用逆动力学QP输出六个电机力矩。

完成1,188组反馈测试、423组规划测试和51组动力学条件测试。平面双足在标准条件下完成八次实测落脚，前进约0.937m；动力学条件网格通过50组，力矩减半且受40N推扰时出现失稳。传感器漂移和受限摆脚仍会明显压缩可行范围，时空调整也没有在全部条件下优于固定策略。三层分别验证，尚未组成带真实测量延迟的统一双足闭环。

1. 延续问题与实验范围

上一阶段已完成简化倒立摆控制与有限脚掌站立实验，但落脚仍可瞬时切换，缺少完整摆脚约束，也未验证多关节行走。本轮重点是把“数学上可以恢复”和“有约束的机器人能够执行”分开检验。原目录lipm_balance保留，新内容位于lipm_extension。

2. 固定采样率与反馈时序

2.1 测量产生、传输和使用

传感器按独立采样时钟产生带源时间戳的噪声测量，再经延迟和抖动队列到达控制器。丢帧发生在传输环节，乱序旧帧被丢弃。控制器只接受时间戳更新的测量；没有新帧时复用旧测量。初始只提供一帧带噪声的预启动测量，不回退读取当前真实状态。

预测器以已接收的过去测量为起点，结合已经发出的CoP输入向当前时刻传播；不读取未来扰动或当前真实状态。数据年龄超过阈值时停止模型推进并记录原因。这只验证了仿真终止逻辑，不能代替实体机器人的安全停止验证。相关代码在 scripts/network.py、scripts/engine.py。

25Hz传感器每40ms才产生新测量。在100Hz控制下约75%的读取复用旧帧，200Hz控制下约87.5%。提高控制率不会增加信息更新率；它只增加对既有估计的使用次数。图中的P95受控制采样相位影响，不应把微小差异理解为传输性能变化。

3. 双支撑、连续摆脚与步时调整

3.1 约束与规划方法

这一层采用DCM反馈，分别比较固定落脚和时刻、仅位置调整、位置与时刻联合调整。三个策略使用同一套新模型和约束，不与上一版本LQR的无摆脚约束结果直接混排。名义步长0.18m、阶段时长0.6s，共十个支撑阶段和九次交换，结束后继续恢复2s。

双支撑期间将CoP投影到两脚支撑区域的凸包，并构造非负负载比例与各足底内的CoP，使合成CoP与目标一致。这里的负载是简化模型的可行分配，不是接触求解器测出的地面反力。相关代码在 scripts/gait.py。

摆脚使用分段五次多项式，在线重规划保持位置、速度和加速度连续。通过多项式导数的连续极值计算速度、加速度和离地高度界，拒绝超界轨迹；不是仅检查离散采样点，也不是在动画中截断穿地部分。相关代码在 scripts/trajectory.py。

约束设置
双支撑时长0 / 0.12 / 0.20s
步时候选0.45至0.75s，间隔0.05s
摆脚速度界1.2 / 1.8 / 2.4m/s
摆脚加速度界30m/s²
CoP每轴指令变化率5m/s
时间提交每阶段最多提交一次，显著DCM误差时触发

时间选择不持续来回改期；当前阶段的落脚位置仍允许更新，并检查下一阶段摆脚是否可行。初始计划本身不可行时直接拒绝，不用后续调参掩盖启动条件不满足的问题。

3.2 对照结果与代价

固定落脚和时刻0/30/33/3
仅调整落脚位置0/33/30/3

以上为12N·s扰动、2.70s施加、摆脚速度界1.8m/s的三组种子对照。无双支撑时均在CoP变化率约束处被拒绝。0.12s双支撑下位置调整和时空调整都通过3/3；0.20s下固定策略反而通过，而两种调整策略失败。这表明局部调整策略和双支撑长度之间存在耦合，不能断言双支撑越长或优化变量越多越好。

0.12s双支撑下，仅位置调整平均运行7.40s，终端相对原始路线误差约0.0687m；时空调整平均7.45s，误差约0.1273m。两者都恢复到实际支撑附近，但后者对原路线的偏离更大。通过恢复判据不等于路线跟踪更好。当前有限候选和贪心目标没有保证全局最优。

423组中通过175组；135组因CoP变化率不满足、95组因落脚可达范围不足、18组因初始摆脚不可行而停止。较长双支撑会挤占摆脚时间；1.2m/s速度界下的多组初始任务被拒绝，说明任务时长也需要与执行能力共同设计。

4. 关节力矩驱动的平面双足

4.1 模型与控制接口

新建27.2kg的平面双足，包含躯干、左右大腿、小腿和脚掌。基座有前后、竖直和平面俯仰三个自由度且没有执行器；两侧各有髋、膝、踝三个电机。每段腿长0.4m，足底约0.20×0.09m。侧向、滚转和偏航受模型约束，躯干及连杆碰撞做了简化。

逆运动学只用于生成初始站姿。之后控制器读取物理状态，建立全身逆动力学QP，求解关节加速度、电机力矩和预测接触扳手。模拟器仅接收六个电机力矩；QP预测的接触力不直接施加到模型，基座位置和关节轨迹也不被逐帧改写。实际脚掌接触由MuJoCo求解。相关代码在 models/biped.xml、scripts/biped.py。

M(q) qdd + bias(q, qd) = Sᵀ τ + J(q)ᵀ λ + passive
约束：力矩上下限、关节位置和预测速度、支撑足加速度、摩擦与足底力矩界
目标：质心、躯干俯仰、摆脚轨迹，以及小幅姿态正则项

使用OSQP 1.0.4，固定数值容差和自适应rho更新间隔。名义控制100Hz、物理积分1ms。电机力矩上限为每侧80、80、30N·m；预测关节速度界8rad/s，实际超10rad/s终止。接触约束包含非负法向力、|Fx|≤μFz与|My|≤0.09Fz，另限制下一控制时刻的足端速度。

4.3 条件扫描与失败边界

扫描步长0.08/0.12/0.16m、控制率50/100/200Hz、水平推力0/20/40N、摩擦系数0.2/0.4/0.8、力矩比例0.5/0.75/1、不同双支撑时长及0.5ms积分步长。推扰持续0.1s，自2.70s开始。各组只改变对应实验因素，重复配置去重后为51组；包括4组站立检查。

51组中通过50组。唯一未通过条件为步长0.12m、100Hz、双支撑0.12s、摩擦0.8、力矩减半并受40N推扰，在4.191s因躯干姿态或高度越界终止。该例前进约1.083m后失稳，前进得更远并不代表任务完成。完整力矩在同样推扰下完成八步。

本轮只对速度和力矩幅值设置硬约束，没有实现电机力矩变化率或执行器带宽模型。标准运行在0.5s后相邻控制指令的最大力矩变化约51.5N·m，仍可能对真实驱动器不友好。QP耗时是本机离线记录，不代表硬实时保证。

5. 独立检查与实现修正

检查器重新读取保存的轨迹，而不是只采用运行器写出的成功标记。反馈与规划层用独立离散动力学公式重算相邻状态；动力学层从关节状态重新计算足位和质心，并检查实际施加的力矩、关节积分和落脚记录。相关代码在 scripts/verify.py、scripts/tests.py。

实现中修正了两个影响结果的问题。第一，MuJoCo积分后部分运动学缓存仍可能对应上一步状态，直接做雅可比差分会放大Jdot误差；现在先同步运动学，再计算控制量，并加入中央差分回归。第二，摆脚在线改期可能产生很小的负高度，现通过连续极值筛查拒绝该候选，而非裁剪显示。最终批次在这些修正之后重新运行，早期调试结果不混入正式统计。

每个正式批次保存配置、源码哈希与源码快照，校验时核对当前文件与快照一致。录屏是同配置的独立重跑，不增加实验数量。源码包保留配置与汇总结果，原始数组留在本地 runs/。

6. 结论与后续工作

本轮将原先“瞬时落脚的简化平衡”推进到“连续受限摆脚”和“真实关节力矩驱动的平面行走”。能确认的是，在所测试的平面模型及条件范围内，控制器完成了多次实测落脚和前进任务；不能据此宣称完成三维人形机器人控制、真实传感闭环或工业部署。

后续优先把带时间戳的测量与偏置估计接入同一双足控制器，并在相同扰动下比较理想状态与估计状态；其次增加力矩变化率、执行器带宽和接触状态切换检查；再将候选步时与全身可执行性连接，减少规划层可行、动力学层却难以执行的情况。三维扩展和硬件测试在这些接口稳定后再开展。当前内容属于模型控制与仿真验证，不是VLA策略训练。
