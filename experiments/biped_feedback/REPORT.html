双足连续行走与 ZMP 力矩闭环改进报告

2026年11月13日 · 机器人控制算法阶段进展

摘要

本轮针对摆腿动力学、ZMP与关节力矩接口、双支撑过渡及反馈时序开展改进。核对历史版本后确认，后续的lipm_extension已具备六关节力矩驱动的八步行走，本轮不把这部分重复算成新增成果，而是补上规划与实际接触之间的接口和对照。

在同一MuJoCo平面双足中，用同一组质心反馈增益生成加速度与ZMP目标，通过逆动力学QP输出髋、膝、踝力矩。增加平滑负载转移、实际接触核对和力矩变化率限制，并将水平质心的延迟测量接入这套动力学控制。完成94个唯一条件，79个通过；没有把重复无噪声运行计作独立样本。

100Hz、无扰动时，实际压力中心跟踪RMSE由19.41mm降至6.06mm；同时质心误差由0.28mm增至1.26mm，说明更强调ZMP会改变控制目标之间的折中。两组20步行走均完成实际落脚，前进约2.323m，其中一组在行走中承受40N、0.1s推扰。80ms延迟下多数条件失败，不能据此声称控制器已达到实际人形机器人部署水平。

1. 反馈对应的问题与本轮范围

原先的lipm_balance把LIPM步态分析与MuJoCo站立恢复分别验证，确实不能把它们合起来称作物理行走。之后的lipm_extension已补入浮动基座、真实摆腿及八次实测落脚，但三个实验层次仍没有完全连通。

所有新增工作仅在仿真中进行。继续使用27.2kg、9自由度的矢状面模型：三个基座自由度没有执行器，两腿各三个电机。侧向、滚转、偏航受约束；没有使用真实IMU、Jetson或硬件代测。旧目录、旧报告和旧结果保持原样。

2. ZMP到六关节力矩的统一接口

2.1 先统一物理量，再讨论增益

ZMP是地面上的位置，单位为米；踝电机力矩单位为N·m，不能直接把两者数值对应，也不应强行让不同任务的增益相同。

新接口为：

步态参考CoM位置/速度/加速度
        ↓ 同一组水平质心反馈增益
质心加速度目标 a_cmd
        ↓ 恒高、零质心角动量变化近似
ZMP目标 p_cmd
        ↓ 与CoM任务共同进入全身逆动力学QP
六个电机力矩 τ
        ↓ MuJoCo独立求解真实脚地接触
实际接触力、压力中心和机器人运动

外环加速度只计算一次：a_cmd = a_ff + 80(c_ref-c_obs) + 18(v_ref-v_obs)。CoM任务与ZMP目标都使用这个结果，避免两个控制层分别调不同的水平反馈增益。躯干俯仰和摆脚的跟踪增益仍按各自任务设置。

若竖直加速度为a_z，则采用 p_cmd = c_x - c_z*a_x/(g+a_z)；超出当前支撑足范围时先投影到支撑范围。每个足底的扳手以足底site为参考、按世界坐标表示为[Fx,Fz,My]，合成地面压力中心为：

p = Σ(x_i Fz_i - z_i Fx_i - My_i) / ΣFz_i
Σ[(x_i-p_cmd) Fz_i - z_i Fx_i - My_i] ≈ 0

式中的My是足底接触力矩，不是踝关节电机力矩。关节力矩由完整动力学约束确定：M qdd + bias = Sᵀτ + Jᵀλ + passive。浮动基座没有电机，因此QP必须通过支撑脚接触来实现加速度；求出的接触力不会直接施加到模拟器。

2.2 用软目标保留多关节动力学的差异

实际多关节模型并不严格满足恒质心高度和零角动量变化。ZMP平衡因此作为软目标加入，仍保留关节限位、力矩、摩擦、足底力矩和支撑足加速度等约束。最终运动由MuJoCo推进，不按参考直接改写qpos。

新增的“仅CoM任务”对照与“CoM＋ZMP映射”共用本轮模型、步态、双支撑、增益和接触核对，区别是是否显式优化ZMP力矩平衡。这是同版本消融，不把旧报告中不同配置的成绩直接拼在一起。

控制频率（Hz） 实际CoP RMSE：对照→映射（mm） CoM RMSE：对照→映射（mm）
50 23.86 → 13.51 0.64 → 1.37
100 19.41 → 6.06 0.28 → 1.26
200 18.52 → 3.61 0.15 → 1.21

100Hz时压力中心误差下降约68.8%，但质心位置误差由0.28mm增至1.26mm。因此这里能够确认的是映射更明确、压力中心目标跟踪更准，不能概括为所有平衡指标都更好。QP预测CoP也单独保存，不用它替代实际接触测量。

实际CoP在每次新力矩施加前采样，描述当时的真实接触；QP预测对应本次新指令。二者的时间与物理含义不同。压力中心误差统计从0.5s开始；失败运行仅有终止前数据，比较时同时报告是否完成，避免把提前终止的较短轨迹当成更好表现。

相关代码在 scripts/biped.py 的WBC.solve和 scripts/feedback.py 的contact_wrenches、resultant_cop。

3. 摆腿与双支撑的物理执行

3.1 摆腿不是动画或位置强制驱动

沿用每段0.4m的髋膝踝模型、足底真实碰撞和有限电机力矩。逆运动学只在初始化生成站姿；之后摆脚采用五次多项式水平轨迹与C2离地曲线，目标通过QP转为力矩。名义步长0.12m、步时0.6s、离地高度6cm；物理积分1ms。

每次落脚须满足正确侧脚接近目标位置、足底高度在允许范围内，且实际法向力超过10N持续至少15ms。完整成功还要求运行至结束、完成全部落脚、满足前进量和终端足位误差约束。

两组20步条件均在14s内完成20/20次实测落脚。无扰动与40N推扰下前进量均约2.323m；这是平面模型中的连续步行，不是三维人形走路，也不是只用“不倒”作为成功标准。

3.2 双支撑负载与ZMP共同过渡

使用五次平滑函数 s(u)=10u³-15u⁴+6u⁵ 转移计划负载，端点一、二阶导数均为0。参考ZMP按相同负载比例从旧支撑脚中心移到新支撑脚中心；最后一步后渐变到两脚各一半负载，而非一直单脚承重。负载是QP目标，实际负载由接触求解器产生，两者都保留在记录中。

双支撑时长（s） 40N条件实测落脚 最大相邻力矩变化（N·m） 双支撑左足比例平均绝对误差（百分点）
0.0 8/8 42.92 -
0.06 8/8 9.99 14.25
0.12 8/8 5.96 7.00
0.2 8/8 5.75 4.95

本组中，无双支撑也能走完八步，但相邻力矩跳变达到42.92N·m；0.12s双支撑下降至5.96N·m。更长过渡使本组负载跟踪更平滑，但会缩短摆腿可用时间，不能据这几组就断言越长越好。零双支撑没有有效的持续过渡区间，不报告其负载比例平均误差。

3.3 接触核对和力矩变化率

支撑集合仍有名义时间表，但计划需要承重的脚必须实际产生法向力；连续超过40ms仍不足5N则终止，不继续假设它在支撑。计划负载低于5%的卸载脚不触发这一检查。这是对支撑假设的核对，还不是基于触地事件在线重排步时。

另外在QP中约束相邻控制力矩：|τ_k-τ_(k-1)| ≤ rate/hz。0.4s启动承重后启用，测试600和1500N·m/s，在50/100/200Hz及0/40N推扰的12组条件全部通过，保存的实际指令也逐条核对满足界限。此处限制控制指令斜率，没有建立真实电机电流环或带宽模型。

相关代码在 scripts/biped.py 的Plan.loads、Plan.feet、WBC.solve及simulate。

4. 频率、推扰和延迟对照

4.1 相同物理模型中的频率与双向推扰

50/100/200Hz控制、0/+40/-40N水平推扰、两种映射，共18个条件；推扰发生在2.70–2.80s。9个仅CoM对照全部完成，9个显式映射完成8个；未通过项为50Hz后向推扰，因计划支撑没有得到实际接触确认而终止。更准的CoP目标跟踪并没有换来更高的条件通过数。

100Hz的推扰恢复如下。恢复定义为推扰结束后，CoM位置误差小于1cm、速度误差小于0.05m/s、躯干俯仰小于0.03rad，并持续至少0.3s。它是相对运动参考的跟踪恢复，不是静止站立恢复；采样分辨率为10ms。若从推扰结束就持续处于阈值内，记0。

推力（N） 推扰后CoM最大误差：对照→映射（mm） 恢复时间：对照→映射（s）
40 6.96 → 5.72 0.02 → 0.01
-40 10.58 → 14.11 0.15 → 0.37

前向推扰恢复接近，后向推扰下新映射恢复更慢。这提示在当前权重下，压力中心任务与质心、摆腿之间仍有折中；本轮不再通过不断调权重把失败样例“调没”。

4.2 延迟只施加到明确的一条反馈链

传感器以100Hz生成带时间戳的水平CoM位置和速度，分别加入1mm与0.01m/s高斯噪声；经固定20/40/80ms延迟到达外环。控制器不能读取尚未送达的测量，比较保持过去测量与常速度预测。每个组合使用3个固定噪声种子，两个方法配对使用相同测量噪声。初始化只提供一帧带噪的预启动观测。

关节编码器、用于QP的模型状态、竖直CoM与接触测量仍理想，只有水平CoM外环延迟。不能把这解释成整个机器人在所有传感器均延迟的情况下完成行走。

固定延迟（ms） 保持测量：完成 常速度预测：完成 两方法共同完成对数 共同完成时CoM RMSE：保持→预测（mm）
20 9/9 9/9 9 5.19 → 1.88
40 9/9 8/9 8 9.71 → 2.64
80 2/9 3/9 2 37.13 → 9.21

20ms下，两方法均9/9，常速度预测降低了共同完成样本的CoM误差。40ms下，保持测量9/9，预测8/9；预测平均跟踪更准，并不意味着更可靠。80ms下分别只有2/9和3/9通过，这种简单外推不能覆盖较长延迟和接触切换。误差表只在共同完成的配对上比较，不混合提前终止的短轨迹。

全批有9个失败条件在2.70s推扰前已终止，属于延迟、噪声或接触切换自身的问题，不能统称为“抗40N推力失败”。

6. 结论与建议配置

本轮已把CoM外环、ZMP接触力矩目标、摆脚和六电机执行放到同一动力学闭环，并完成20步连续物理行走。双支撑明显降低了本组力矩跳变，显式ZMP目标改善了实际压力中心跟踪，同时暴露了CoM误差、后向恢复和低频接触转换的代价。

当前可继续研究的起点是100或200Hz、0.12s双支撑、水平CoM反馈延迟不超过20ms的本模型配置。这个选择只基于已测条件，不是硬件推荐值或安全保证。常速度预测在较短延迟时有用，但尚不能作为80ms延迟的解决方案。

下一步若继续，优先把名义支撑时序改为触地事件驱动的有限调整，再考虑带接触状态和执行器带宽的状态估计。三维模型、地形与真机需要另行验证，不与本轮平面结果混写。
